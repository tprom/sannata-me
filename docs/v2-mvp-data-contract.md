# MVP-контракт данных для Agent 2.0

Дата: 2026-02-24  
Статус: согласовано для внедрения в версии 1.x как подготовка к 2.0

## 1) Цель контракта

Зафиксировать минимальную структуру данных и правила валидации, чтобы:

- разделить сущности «Город» и «Достопримечательность»;
- поддержать будущий пункт меню «Показать на карте»;
- не выполнять повторную массовую правку данных при переходе к Agent 2.0.

---

## 2) Сущности (MVP)

## 2.1 City (город)

Город является источником истины для:

- привязки к стране;
- локализованных названий;
- геоданных города;
- готовности к отображению на контурной карте.

### Обязательные поля

- `cityId: string` — стабильный ID (UUID/slug-id), не меняется после создания.
- `slug: string` — URL-идентификатор.
- `countryId: string` — связь со страной/картой.
- `name: { ru: string, en: string, de: string, uk: string }` — полная локализация названия.
- `geo: { lat: number, lng: number, source: string }` — координаты города и источник.
- `menu: { hasMapOption: boolean }` — включение второго пункта меню.
- `status: { geoReady: boolean }` — готовность к показу на карте.

### Рекомендуемые поля

- `mapAnchor: { x?: number, y?: number, transformVersion?: string, confidence?: number }`
- `geoMeta: { accuracyClass?: "approx" | "verified", lastCheckedAt?: string, checkedBy?: string }`

---

## 2.2 Landmark (достопримечательность)

Достопримечательность не создаёт и не редактирует данные города.

### Обязательные поля

- `landmarkId: string` — стабильный ID.
- `slug: string`
- `cityId: string` — обязательная ссылка на существующий город.
- `title: string` (или локализованный объект по текущей модели проекта)
- `content` — по текущей контентной схеме модуля.

### Рекомендуемые (опциональные, можно хранить уже сейчас)

- `geo?: { lat: number, lng: number, source?: string }`
- `mapVisibility?: "city-only" | "show-own-pin"`
- `sortOrder?: number`

Примечание: в MVP геоданные Landmark можно не использовать в UI, но хранить для будущего расширения.

---

## 2.3 MapCalibration (калибровка карты страны)

Хранится отдельно от City/Landmark, обычно на уровне страны.

### Обязательные поля

- `mapId: string`
- `countryId: string`
- `image: { width: number, height: number }`
- `transform: { type: "affine", version: string }`
- `calibrationPoints: Array<{ lat: number, lng: number, x: number, y: number }>`

### Минимум для MVP

- не менее 3 реперных точек;
- рекомендуется 5–8 точек для визуально стабильного результата.

---

## 3) Правила валидации

## 3.1 Общие

- Все ID уникальны и неизменяемы после создания.
- Все ссылки между сущностями проверяются (referential integrity).
- Все изменения сохраняются с `updatedAt`.

## 3.2 Валидация City

- `lat` в диапазоне `[-90, 90]`.
- `lng` в диапазоне `[-180, 180]`.
- Все локали `ru/en/de/uk` обязательны (допускается fallback на этапе UI, но не в мастер-данных).
- Если `menu.hasMapOption = true`, то `status.geoReady = true` обязательно.

## 3.3 Валидация Landmark

- `cityId` обязан ссылаться на существующий City.
- Создание Landmark без `cityId` запрещено.
- Если заполнено `geo`, применяются диапазоны как для City.

## 3.4 Валидация MapCalibration

- `calibrationPoints.length >= 3`.
- `x` в диапазоне `[0, width]`, `y` в диапазоне `[0, height]`.
- `transform.type` для MVP только `affine`.

---

## 4) Формы (MVP)

## 4.1 Отдельная форма City

Форма создаёт/редактирует только City.

### Минимальные поля формы

- `cityId` (генерируется)
- `slug`
- `countryId`
- `name.ru`, `name.en`, `name.de`, `name.uk`
- `geo.lat`, `geo.lng`, `geo.source`
- `menu.hasMapOption`
- `status.geoReady`

### Поведение

- Сохраняет только сущность City.
- Не создаёт Landmark.

## 4.2 Форма Landmark

Форма создаёт/редактирует только Landmark.

### Минимальные поля формы

- `landmarkId` (генерируется)
- `slug`
- `cityId` (select из существующих City)
- `title`
- `content`

### Дополнительно (опционально)

- `geo.lat`, `geo.lng`, `geo.source`
- `mapVisibility`

### Поведение

- Создание нового города из формы Landmark запрещено.
- Поле `cityId` обязательно.

---

## 5) Правила меню (MVP)

Для каждого города отображаются два действия:

1. `Открыть город`
2. `Показать на карте`

Условие для пункта 2:

- `menu.hasMapOption = true`
- `status.geoReady = true`

Если условие не выполнено:

- пункт 2 неактивен (disabled) с понятной причиной.

---

## 6) Ограничения MVP

- Точность геопривязки: визуальная правдоподобность, не геодезическая точность.
- Внешние картографические SDK в рантайме не требуются.
- Расчёт `mapAnchor(x,y)` допускается офлайн/на сервере и кэшируется в City.

---

## 7) Совместимость с текущей версией

На текущем этапе достаточно:

- добавить City-поля в мастер-данные;
- перевести Landmark на обязательный `cityId`;
- не ломать существующий контентный формат карточек;
- хранить опциональные geo-поля Landmark без обязательного использования.

Это минимизирует будущие миграции при запуске Agent 2.0.
