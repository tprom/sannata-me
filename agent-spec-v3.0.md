# Модуль Agent — Спецификация v3.0

Статус: согласовано
Дата: 2026-02-15

## 1) Цель версии

Версия 3.0 завершает контур генерации литературного текста и фиксирует агент как административный модуль:

- ввод и хранение подготовленного контента на 4 языках;
- управление графическими блоками открытки;
- управление галереей (ввод файлов и метаданных);
- формирование 4 локализованных файлов представления (`view.ru.json`, `view.en.json`, `view.de.json`, `view.uk.json`).

## 2) Форма (UI) — финальный контракт

### 2.1 Метаданные

Обязательные поля:

- `city.en` — поле с выпадающим списком существующих городов + возможность ручного ввода;
- `city.de` — текстовое поле;
- `city.ru` — текстовое поле;
- `city.uk` — текстовое поле;
- `landmark` — единое поле достопримечательности (без перевода), с выпадающим списком существующих достопримечательностей + ручной ввод.

Служебные поля:

- `citySlug` — вычисляется из `city.en`;
- `landmarkSlug` — вычисляется из `landmark`;
- `alias` — вычисляется как `[citySlug]-[landmarkSlug]`.

### 2.2 Контент

Вместо 8 блоков используются 4 `textarea`:

- `content.ru`
- `content.en`
- `content.de`
- `content.uk`

Каждое поле содержит готовый итоговый текст открытки на соответствующем языке.

### 2.3 Графический блок открытки

Новые поля загрузки:

- `postcardGraphics.stamp.upload`
- `postcardGraphics.illustrations.2L.upload`
- `postcardGraphics.illustrations.2R.upload`
- `postcardGraphics.illustrations.4L.upload`
- `postcardGraphics.illustrations.4R.upload`

Правила:

- Блок считается **активным**, если файл загружен.
- Если файл не загружен, блок **неактивен**.
- Для неактивного блока место в итоговом тексте не резервируется.

### 2.4 Галерея

Блок ввода изображений для галереи остается без изменений (текущая структура и поведение).

### 2.5 Кнопки

Все кнопки формы и их поведение остаются без изменений.

## 4) Контракт локализованных `view*.json`

Оркестратор формирует 4 файла:

- `view.ru.json`
- `view.en.json`
- `view.de.json`
- `view.uk.json`

Путь:

`data/landmarks/{citySlug}/{landmarkSlug}/view.{lang}.json`

Пример:

```json
{
  "greeting": "Привет тебе от Колизея",
  "stampImage": "stamp/stamp.png",
  "contentFile": "Абзац 1...\n\nАбзац 2...\n\n[[illustration:illustrations/2l.png|left]]\n\nАбзац 3...\n\nАбзац 4...\n\n[[illustration:illustrations/4r.png|right]]",
  "footer": "Посмотри всю историю - тебе понравится"
}
```

> Поля `greeting` и `footer` в текущем контракте остаются. При необходимости локализации этих строк в будущей версии они могут быть расширены до языковых блоков.

## 5) Правила внедрения иллюстраций в текст

Иллюстрации внедряются только для абзацев `2` и `4`:

- `2L` → `[[illustration:{path}|left]]` около абзаца 2
- `2R` → `[[illustration:{path}|right]]` около абзаца 2
- `4L` → `[[illustration:{path}|left]]` около абзаца 4
- `4R` → `[[illustration:{path}|right]]` около абзаца 4

Правила вставки:

- вставка выполняется только если соответствующий блок активен (`isActive: true`);
- если блок неактивен, маркер не добавляется;
- место под отсутствующий блок не резервируется;
- если активны оба блока абзаца (например `2L` и `2R`), вставляются оба маркера.

## 6) Оркестратор v3.0 — рамки ответственности

Оркестратор выполняет только:

1. обработку изображений галереи через AI-пайплайн (фотореалистические копии на основе промптов);
2. сборку локализованных `view.{lang}.json` из `data.json`.

Что исключается:

- генерация литературного текста;
- этапы `plan/generate paragraphs`;
- использование промежуточного JSON-источника для текста.

## 7) Нормативные инварианты

- master-источник данных — один `data.json` на объект;
- локализованные представления — четыре отдельных `view.{lang}.json`;
- `citySlug` строится строго из `city.en`;
- `landmark` хранится в одном поле (без языковых вариантов).
